## Canonical category and naming families

The **three established, independently callable research software assets** are Knowledge Workflow (native runtime and portable knowledge sub-workflow), Evidence Tool (independent evidence checking) and Bio Tool (FASTA/PDB bounded data processing). An independently packaged **experimental Framework** is a peer software-contract experiment, not a fourth established biological research asset.

The remaining planes are GitHub-native execution infrastructure, accepted Git-backed production state, independent proposal-only Agent work, institutional public-reference checks, independent project custom checks, dated field cases, standards/metadata, governance, test fixtures and versioned historical review.

| Category ID | Meaning and stable boundary |
| --- | --- |
| KNOWLEDGE_WORKFLOW / EVIDENCE_TOOL / BIO_TOOL | Separate, callable software assets; software correctness is not scientific validity |
| EXPERIMENTAL_FRAMEWORK | Independently packaged synthetic software-contract challenge; no scientific model-execution claim |
| GITHUB_NATIVE_INFRASTRUCTURE | Nine Actions and shared helpers, not nine research products |
| ACCEPTED_PRODUCTION_STATE | Actual accepted data, event chain and Receipts; placeholders are explicitly marked |
| HISTORICAL_PROVENANCE | Frozen observations, historical reports, corrections and living evidence index distinguished by file role |
| PUBLIC_RESEARCH_LESSONS | Reviewed methods, negative results and failure modes, not accepted scientific discoveries |
| AGENT_PROPOSAL_AND_REVIEW / SCIENTIFIC_FIELD_CASE | Agent handoffs, reviewer statements and replaceable research cases; no automatic write authority |
| OFFICIAL_REFERENCE_OBSERVATION / PROJECT_CUSTOM_CHECKS | Two separate daily verification planes with independent original/report authority |
| EXTERNAL_INTEROPERABILITY_AND_IDENTITY | Provider-owned identities and project declarations, without implied third-party validation |
| VALIDATION_AND_REGRESSION / PUBLIC_GOVERNANCE_AND_METHOD / REPOSITORY_GOVERNANCE / BUILD_AND_REPOSITORY_CONFIG | Tests, documentation, permissions, public software contracts and repository configuration |

An individual file can support multiple workflows, but its registry assigns a **primary classification** and separate evidence role. The inventory covers each file by its original path, not by copying or relocating its bytes.

## REVIEW → REPLAY · Naming governance

1. Preserve original Git identities, historical PR/Run names, published links, immutable archived reports, accepted production bytes and provider-owned IDs
2. Give every baseline file, main commit and historical PR a canonical review category without reclassifying an old archive as a live scientific result
3. Correct misleading headings and navigational statements in **living** documents; link to the date-pinned immutable original evidence for every revision
4. Keep named failure, uncertainty, dissent and closed-unmerged records; never coerce unknown into zero
5. Use the [independent offline contract tests](../../tests/test_first_day_taxonomy.py), full native CI, PR review and a final remote main check

The fixed method is **DEFINE → PIN → QUALIFY → EXECUTE → EVALUATE → AUDIT → REVIEW → REPLAY**. Categorizing a historical Commit or PR does not assert every research stage occurred or was scientifically accepted.
