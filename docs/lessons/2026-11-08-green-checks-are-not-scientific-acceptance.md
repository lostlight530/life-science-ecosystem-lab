**Observed mechanism:** a single documentation PR can produce multiple independent GitHub `push`, `pull_request` and post-merge `push` checks. All 20 new Runs succeeded, but two Bio `pinned-field` Jobs on ordinary `push` were intentionally `skipped`, and none issued a new accepted Knowledge `data/` Receipt. A 100% green set of these specific visible Run outcomes therefore demonstrates neither universally executed Bio samples nor new scientific results

**Counterexample and correction:** the previous frozen 768-ID census and the current 788-ID census reconcile exactly, while four preserved receipts and event-chain entries remain unchanged. Compare `run_id`, `attempt`, `event`, `branch`, `head_sha`, actual Job conclusions, Artifact provenance and accepted Git Blob separately. A `push` success with a skipped expensive/conditional Job must not be translated into successful execution of that Job. Likewise, branch-only work, an external provider account, WorkflowHub metadata and publication identifiers have different authorities

**Clock failure mode:** the four Nov 7–8 schedule Runs were created 06:05:53, 06:52:45, 06:17:17 and 07:05:01 after their nominal crons. These are measured nominal-to-`created_at` gaps, **not** observed queue wait, dispatch delay, uptime failure or malicious action. Keep each clock and refrain from attributing causes without runner/provider timing evidence
